# Tech stack decision

## Short answer

**Python (FastAPI) for the gateway and backend. TypeScript for everything that
runs in a browser or editor.** Not "Python or Node": each piece uses the
language its platform needs.

| Piece | Choice | Why |
|---|---|---|
| Gateway + management API | Python 3.12, FastAPI, httpx, uvicorn | Async I/O is all the hot path does; FastAPI is fast enough for < 10 ms overhead; Python is the team's strongest language and fits the later Distiller (ML) work. |
| Live counters | Redis 7 + Lua scripts | Atomic check-and-reserve in one round trip, so 100 parallel calls can't overspend. |
| History + policies | Postgres 16 (SQLAlchemy 2 async + Alembic) | Usage history, policies, tenants. |
| Background jobs (alerts, reconciliation) | arq (Redis-based async worker) | Same Redis, same async style. |
| Web dashboard | React + Vite + TypeScript, TanStack Query, Recharts, Tailwind | Fast to build, shares types with extensions. |
| Browser extension | Manifest V3, TypeScript, Vite (CRXJS plugin) | Browsers only run JS. |
| VS Code extension | TypeScript, VS Code Extension API | VS Code only runs JS/TS extensions. |
| SDKs | Python package + npm package | Agents are written in both. |
| Tests | pytest + pytest-asyncio, Vitest, Locust for load | |
| Dev env | Docker Compose, uv (Python), pnpm workspaces (JS) | |

## Why not Node for the gateway?

Node would work fine, and it would let the whole repo be one language. The
reasons to stay with Python:

1. The bottleneck is network I/O to the LLM provider (hundreds of ms), not the
   firewall's own CPU. Both runtimes add only a few ms; Redis round trips dominate.
2. The project brief, the Distiller upsell and your skill set are all Python.
3. The parts that *must* be JS (dashboard, extensions) talk to the gateway over
   HTTP, so they don't care what it's written in.

Revisit only if load tests show the Python process can't hold < 10 ms p50 at
target RPS. The first fix then is more uvicorn workers, not a rewrite.

## Contracts shared across languages

- `shared/pricing/models.json`: model price table, read by the gateway and shown
  by the dashboard.
- `shared/policy-schema/policy.schema.json`: JSON Schema for policy YAML,
  validated by the gateway and used for autocomplete in the VS Code extension.
- The management API's OpenAPI spec (generated by FastAPI) is used to generate
  the TypeScript client for the dashboard and extensions.
